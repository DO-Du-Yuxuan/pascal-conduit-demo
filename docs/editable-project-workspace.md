# 可编辑项目与工作区持久化

当前外部文件是统一 `schemaVersion: "4.0"` Project JSON，格式见 [统一项目合同](unified-project-json.md) 和 [ADR 0005](adr/0005-unified-project-file.md)。顶部导入和导出都作用于同一份文件；2D 和 3D 不再提供单独的 Overlay 文件入口。3.0 及更早格式不迁移且拒绝导入；旧双文件需由外部流程另行转换。未编辑建筑、未知合法未来系统节点与字段按原始数据保留。具体目录及拒绝规则见 [统一项目合同](unified-project-json.md) 与 [ADR 0006](adr/0006-project-4-system-catalog.md)。

应用启动时工作区为空，不自动加载示例项目。用户从顶部“导入 JSON”选择统一项目后才显示模型；未导入时导出和 3D 视图不可用。

内部工作区仍用建筑 Project 和施工 Overlay 两个快照支持现有编辑及按时间排序的撤销/重做。它们只是同一文件的内存表示。任一侧发生修改都提示存在未保存项目；导出成功才同时清除脏状态。取消保存或写入失败保留当前工作区和脏状态。无效导入会报告错误，当前工作区不会被替换。`pascalConduitProjectId` 是稳定身份，SHA-256 是文件修订指纹。

导入建筑节点仍为只读，文档化的 Demo Beam 是唯一建筑作者扩展。新增或删除 Beam 时，同一事务仅同步其所属 `Level.children` 中的 Beam ID；楼层的其余原始字段不可编辑。施工设备、路线、端口、控制关系和图纸布局写入系统或 Drawing 节点，不修改其他建筑数据。

自动图纸布局与手工引线通过同一工作区事务参与撤销/重做。无图纸且无持久图纸内容时导出仍无图纸；首次保存图纸内容时按楼层创建默认施工图。同层其他图纸及其布局不会被当前画布写入覆盖。手工测量始终留在会话内。

## 渲染错误恢复

React Error Boundary 捕获其包裹子树中的渲染、构造与生命周期错误后，独立错误页可从共享工作区 store 读取崩溃时最后一次已提交的 Project 与 Overlay，并通过与正常保存相同的 `encodeUnifiedProject(project.raw, overlay)` 编码为统一 schema 4.0 Project JSON。store 中 Project/Overlay 文档引用改变时，模块级恢复缓存提前编码最近一次成功的完整工作区；纯预览更新不会触发编码。错误页点击下载时优先即时编码当前 store 快照，若失败则提供最近一次成功缓存并在提示和文件名中标明回退。没有成功编码过的完整项目时禁用恢复导出。该文件保留原始 Project 树、稳定 ID 和未知合法字段；尚未提交的绘制草稿、鼠标预览和其他纯会话 UI 状态不在恢复文件内。

诊断报告为独立 JSON，不包含 Project 正文；记录错误名称/信息/原始调用栈、React componentStack、构建版本/提交号/时间、去除查询参数和片段后的页面 URL、浏览器 user agent、项目 ID、导入源 SHA 与 Project/Overlay 脏状态，以及最近成功恢复快照的时间和本次导出是否使用回退缓存。生产构建提供 source map，以便结合 bundle 行列和构建提交追溯源码。Minified React error #185 的错误页附 React 官方错误说明并解释其为更新深度超限循环。

边界：Error Boundary 不能恢复整个浏览器或标签页进程崩溃，通常也不捕获事件处理器、异步回调或边界自身的错误；因此本功能保证的是仍可显示 React 错误页时导出最后已提交的工作区快照，不是后台自动持久化或崩溃前所有临时编辑状态的保证。
