# Pascal JSON 只读 3D 查看器

## 边界

3D Viewer 是一个本地展示层。它从 `Parsed.nodes`、根节点、材质、集合与插件信息制作 JSON 深拷贝，并由独立适配渲染层消费该副本。唯一例外是文档化的 Demo `beam` 扩展：3D 梁工具可通过统一工作区事务写入新的 Beam 项目节点；其他导入 Pascal 节点仍只读。为保证大型家具场景可交互，画布使用轻量 WebGL 几何展示，不启动 Pascal 发布包中会造成卡顿的 WebGPU 后处理链路。相机、图层、隐藏与选择状态不会修改导入 JSON 或 Parser 输出。

施工管线、设备、槽孔和施工图信息保存在统一 `schemaVersion: "4.0"` Project JSON 的系统及 Drawing 节点中；编辑器内部仍用 Overlay 适配结构；3D Viewer 只读取 Pascal 建筑底图和 Overlay，不能把展示状态写回任一数据源。3D 中看到的剖切、隐藏、爆炸、单层与漫游画面均只是当前会话的展示状态。强电箱和弱电箱都在设备下沿、上沿各横向排列 10 个物理孔；强电箱的插座与照明系统共用这 20 个孔，任一系统占用后另一系统不能重复占用，弱电箱的 20 个孔供网络线路使用。新建箱体的首排孔位沿用横向和上下排定位，但其管线中心落在安装宿主表面，和普通墙面管线保持同一敷设深度；额外端口才沿宿主法线进入后续排。这些是 Overlay 中的真实端口位置，不会为新增管线挤压既有管线。画管起点尚未确认时，悬停到电箱才显示当前系统可选的孔位；只有单击具体孔位才会起管，箱体本身不再回退选择首孔。路线已起画时，悬停目标设备显示端口辅助对齐或连接提示，左键点击端口或设备本体均按最近兼容开放端口处理；辅助对齐只确认下一落点，不连接设备。从 86 底盒出发的路线也可连接目标设备端口。已接源线路的开放管端在画管模式显示可点击绿点：尚未起画时点击它可从该端续画；已有同系统草稿时点击它可确认辅助对齐点，仍需继续绘制，不会暗中合并两条管道。

普通点位（包括灯具）的 3D 定位均从点位中心量取。墙面点位的左右方向沿墙体轴线：先遇到同墙同高度的另一点位时量到对方中心，否则量到墙端或洞口边；向上量到宿主墙顶，向下量到楼板顶面。属性框的墙面左右标签按当前相机的屏幕方向显示，并根据见证点区分另一点位中心、洞口边、墙边、墙顶和地面。梁面、天花及楼板点位沿安装面两个轴量到首个实体表面；同一非墙宿主上的其他点位若与尺寸轴的横向偏差不超过 100 mm，也可作为中心到中心目标。此时尺寸值使用两点实际中心距离，尺寸线端落在另一点中心；连接射线若先碰到实体，实体交点优先。编辑该值时沿当前轴调整，横向偏差保持不变；小于横向偏差的输入无效。参考平面点位另有一条向下尺寸，止于首个实体表面。墙面左右射线略入墙厚后再求交，避免沿墙面共面导致漏掉墙端和洞口边。非墙宿主的定位尺寸线及端点为避免与宿主共面而沿宿主法线抬高 25 mm，数值仍以原始未偏移的物理见证计算。点位尺寸标签按稳定顺序分配不同屏幕位置，避免四向标签重叠。内机、梁和风口等施工净空对象仍从真实实体外廓量取，但共用场景尺寸线外观。

HVAC 也是统一项目中 HVACSystem-owned 施工数据：室内空调风机、矩形送/回风管、风口、Ctrl 创建的墙体矩形穿孔、86 控温器以及一对一控制关系均不属于 Pascal 节点。空调是与点位、梁同级的编辑工具，空调区也必须保留同一放置模式的“放内机”和“画风管”明确入口；空调区只在空调模式或选中空调对象时显示。悬停放置会显示完整但不可拾取的内机预览，因此底下的合法 Ceiling、梁面或布局参考面仍能接收落点点击；放置点定义为内机底面，放内机模式同时提供共享 Layout reference plane 的显示开关和高度输入。辅助面不参与风管绘制：点击“画风管”后，直接点击蓝色送风口或橙色回风口会自动开始对应路线。首段矩形风管按所点端口的外向截面方向离开并随内机 yaw 旋转；确认首段后才按鼠标选择正交方向。单击始终只确认一个拐点，双击或 Enter 才提交已经确认的整条风管。预览默认正交，Shift 切换，← / ↑ / → 锁定 X / Y / Z，↓ 取消世界轴；世界轴仍可悬空绘制。加风口时，鼠标命中的风管外表面决定开口面和沿段位置，并显示强对比白色默认尺寸预览；单击才创建。该物理面在创建后固定，选中已创建风口时，以开口两端到所在管面边缘的两条橙色尺寸线和起点/终点净距字段调整沿段位置，领域校验继续拒绝越出所在面的尺寸或位置。选中未接管内机时，属性区提供底部标高及 `+X`、`−X`、`+Z`、`−Z` 四个水平净距：每条 3D 尺寸线从内机真实外廓的世界轴向边界起算，并止于该方向首个墙实体面或垂直范围相交的另一台内机实体面；绝不从对象中心点起算。接管后定位和旋转锁定。当前只支持每台内机各一条不分支的送风和回风路线、直段和固定 90° 弯头；不自动路由、拉伸、变径或生成施工合规结论。

已连接任一风管的内机位置和水平旋转锁定，避免暗中移动端口或重布路径；共享风管截面仍可编辑并同步到两条路线。墙体穿孔的净空固定为共享截面宽高各加 50 mm，作为统一项目 `HVACSystem.wallPenetrations` 的施工证据保存，而非只读建筑修改或结构审批。控温器仅可放到墙或梁侧面；其到内机的逻辑关联与电气管线无关，并在 2D、3D 中以灯控同款虚线显示。选中墙面控温器后，3D 与普通墙面点位一样显示安装面内上、下、左、右四向中心定位尺寸；输入框回车或失焦可按任一方向调整位置，且不改动其内机关联。2D 空调图按同一内机外廓、端口宽度、风管截面宽度、风口位置和控温器 86 mm 外廓投影，端口以内嵌“送”/“回”色块区分；控温器显示墙面标高与定位尺寸，内机尺寸从外壳实体边缘量到该方向第一次命中的墙体实体面，直风管显示端点长度，截面以可移动说明框表达。

当 2D 与 3D 同时打开同一项目时，3D 在提交设备编辑前会同步共享 Overlay；因此 2D 已保存的点位说明框、定位尺寸数字和尺寸线位置会随 3D 高度编辑保留。自动说明框和点位定位尺寸首次显示时会保存分组、横竖排、行顺序、文字框位置、尺寸数字位置与尺寸线偏移；高度编辑只更新其 `H=` 值，不触发重新分组或重建既有定位尺寸链的绘图位置。墙上定位尺寸链在端部优先命中相接墙的房间侧实体面；没有相接墙时使用本墙实体端面，显示值始终由绘制的实体见证点直接计算。新增点位只保存其相关的新布局记录，不覆盖现有记录。删除点位、改变平面宿主/类型/系统或改变已保存组的成员时，才会使受影响派生标注不再适用。

有效 Demo Beam 的底面、侧面和端面可作为施工管线宿主；顶面与 Ceiling 相接，不可选择。梁面路由保持明装且不产生槽。从墙面已确认管端继续绘制时，明确命中的梁面优先成为预览和确认落点；正交锁定时，落点是受约束方向与该梁面的真实交点，而不是原始鼠标命中点。若该方向无法抵达梁面，单击会确认当前墙/天花上的辅助对齐点，用户可继续逐点转向梁面，不会生成自由的斜向连接或卡住绘制会话。Ceiling 与梁之间沿用同一规则。梁面上的电气转角显示直角弯配件，其余电气大弯使用 150 mm 半径。渲染器之外的解析碰撞检查仍会把有效梁实体作为障碍物，因此悬空和世界轴向管段进入梁体也会显示红色冲突并阻止提交；无效导入梁不会成为宿主或障碍物。

所有当前设备类型也可选择有效 Beam 的底面、侧面和端面；显示几何和端口按该面法线与基准定向，顶面不会成为点位候选。2D+3D 分屏中在 2D 选择 Overlay 点位，会同步成为 3D 面板的活动点位，可直接输入定位尺寸；这不赋予 2D 编辑能力。允许 Ceiling 安装的点位在实际 Ceiling、梁或楼板上被选中后，提供安装面四向尺寸和相对完成地的标高输入；首次修改会保留其世界坐标并改为独立 Installation reference plane 关系。参考平面点位另外向下量到首个实体表面，并保留单独的完成地标高输入与多选统一改标高。墙面点位只把同墙且中心高度相同的另一点位作为水平尺寸目标，距离量到对方中心；梁、天花、楼板等非墙宿主也可使用同宿主、同一面的其他点位作为中心目标，横向偏差容许 100 mm，显示值为实际中心距，射线/连线更早命中真实建筑表面时由该实体作为见证。管线、参考平面和不同宿主的点位不参与。墙端、洞口、楼板、墙顶以及与尺寸射线相交的梁、天花、门窗可成为实体见证点；家具及其 Viewer 占位外廓始终不参与尺寸测量，家具图层开关不改变读数；墙面向上尺寸固定量到宿主墙顶，向下量到楼板顶面。参考面不参与。当前 Viewer 不显示 Column 柱体，因此柱体暂不参与尺寸。图层显隐不改变真实几何见证点。无目标的方向不显示数值或尺寸线；非墙宿主的显示线段沿宿主法线抬高 25 mm，标签在屏幕空间按稳定次序分开。FCU 内机和风口继续按各自外廓量净距。编辑梁不会拖动设备或管线：仍接触该面的关系保留，失效关系会在同一工作区事务中清除为未宿主。仍承载设备的梁会拒绝删除并显示设备身份；未承载时仅清理该梁穿孔，不改写剩余管线坐标。这些可视化记录不构成荷载、配筋、开孔安全区、规范或结构审批结论。

3D 建筑展示不写入 Drawing。2D 自动尺寸与施工标注的布局及来源证据保存在楼层默认施工图；同楼层其他 Drawing 原样保留。2D 手工测量仍只属于当前会话。

## 数据诚实性与降级

- 仅传递源 JSON 已有的节点和变换；根节点缺失时仅从 `parentId` 为空的节点推导，并显示诊断。
- `slab.elevation` 在 Pascal 中表示从本层 Y=0 向上的楼板厚度；3D 按该厚度挤出楼板，并把位于其 polygon 内、普通落地家具的源 Y 坐标放在楼板顶面之上。墙面/天花附着对象不套用该抬升。
- `roof` / `roof-segment` 缺失时显示“当前文件无屋顶数据”，不得补造屋顶。
- 未承诺的第三方节点保留在输入中并显示信息诊断。
- 不加载 GLB；家具统一以由源 `asset.dimensions × item.scale` 得出的尺寸占位展示，避免在一个场景中并发请求大量模型。

## 展示控制

Builder 风格底部主栏提供「系统」入口，第二行列出十个系统。选系统只切换左侧常驻栏的工具卡片，不改变当前视图；未选择系统时系统栏为空，未实现的系统在选中后明确显示空状态。电气、照明、空调、智能、消防的卡片按“放置设备 / 绘制 / 编辑动作”分区并锁定目录。弱电箱和网络面板归电气；温湿度传感器归空调；RFID 读写器归智能；强电箱从电气创建，照明管复用其端口。选中 FCU 后，温控器关联从内机对象属性发起，不提供单独目录卡片。给排水、净水、卫浴、灌溉、燃气仍显示系统入口和明确空状态。点击已有设备、管线、风管或梁的创作卡片时，纯 2D 进入 3D，分屏保留分屏。3D 路线参数和创作辅助工具位于可调宽、可隐藏的常驻左栏；选中对象后，其属性显示在画布右侧的窄悬浮框，按所属系统命名，取消选择即关闭。当前未接入的 Builder 主栏动作禁用，不会写入项目数据。

画布左上角提供 3D、2D、分屏与单一楼层选择。分屏中的建筑 3D 视图与 2D 图纸同步显示所选楼层；系统创作卡片只在开始创作时将纯 2D 切至 3D。3D 画布右上角的「图层」弹层只控制 3D：建筑组提供墙体、梁、楼板、天花、屋顶、门窗、家具与楼梯、空间名称；施工组提供插座、照明、网络、消防、传感器和空调。建筑层使用 3D Viewer 的会话态显隐；施工层复用 Overlay 中既有系统、传感器和 HVAC 可见性字段，保持其 Project 持久化语义；左侧创作工具不再提供重复的 3D 管线图层菜单。它们与 2D 左侧「图纸」标签中的图层开关相互独立。旧 3D 顶部的外观/室内、视角、投影、叠放/爆炸和墙体详细控件已移除。底部主栏保留顶视图快捷入口。相机仍可鼠标旋转、右键平移和滚轮缩放；相机与建筑图层状态只保存在当前 React 会话。

创建或编辑 Beam 会更新建筑项目数据，但不会重置用户已调整的相机位置或角度；只有用户选择镜头预设或重建画布时才应用预设视角。


Project JSON 版本边界为 4.0：3.0 及更早格式和退休公共类型会被拒绝导入，不提供自动迁移。公开目录使用 `NetworkOutlet`、`Spotlight`、`FanCoilUnit`、`FCUThermostat`、`TemperatureHumiditySensor`、`RFIDReader`、`GalvanizedSheetMetalDuct` 等具体类型；内部 Overlay 通用名仅是适配实现细节。消防管以 `FireWaterPipe` 自由起画，不需要入户点，不创建 Circuit；弯头、三通、直接接头分别使用 `FireWaterPipeElbow`、`FireWaterPipeTee`、`FireWaterPipeConnector`。FCU 默认外壳为 1000 × 600 × 300 mm，镀锌铁皮风管截面为 500 × 200 mm。
