# Pascal JSON 只读 3D 查看器

## 边界

3D Viewer 是一个本地展示层。它从 `Parsed.nodes`、根节点、材质、集合与插件信息制作 JSON 深拷贝，并由独立适配渲染层消费该副本。唯一例外是文档化的 Demo `beam` 扩展：3D 梁工具可通过统一工作区事务写入新的 Beam 项目节点；其他导入 Pascal 节点仍只读。为保证大型家具场景可交互，画布使用轻量 WebGL 几何展示，不启动 Pascal 发布包中会造成卡顿的 WebGPU 后处理链路。相机、图层、隐藏与选择状态不会修改导入 JSON 或 Parser 输出。

施工管线、设备、槽孔和施工图信息继续保存在独立 Overlay 中；3D Viewer 只读取 Pascal 建筑底图和 Overlay，不能把展示状态写回任一数据源。3D 中看到的剖切、隐藏、爆炸、单层与漫游画面均只是当前会话的展示状态。

当 2D 与 3D 同时打开同一项目时，3D 在提交设备编辑前会同步共享 Overlay；因此 2D 已保存的点位说明框、定位尺寸数字和尺寸线位置会随 3D 高度编辑保留。自动说明框和点位定位尺寸首次显示时会保存分组、横竖排、行顺序、文字框位置、尺寸数字位置与尺寸线偏移；高度编辑只更新其 `H=` 值，不触发重新分组或重建既有定位尺寸链的绘图位置。新增点位只保存其相关的新布局记录，不覆盖现有记录。删除点位、改变平面宿主/类型/系统或改变已保存组的成员时，才会使受影响派生标注不再适用。

有效 Demo Beam 的底面、侧面和端面可作为施工管线宿主；顶面与 Ceiling 相接，不可选择。梁面路由保持明装且不产生槽。从墙面已确认管端继续绘制时，明确命中的梁面优先成为预览和确认落点；正交锁定时，落点是受约束方向与该梁面的真实交点，而不是原始鼠标命中点。若该方向无法抵达梁面，单击会确认当前墙/天花上的辅助对齐点，用户可继续逐点转向梁面，不会生成自由的斜向连接或卡住绘制会话。Ceiling 与梁之间沿用同一规则。梁面上的电气转角显示直角弯配件，其余电气大弯使用 150 mm 半径。渲染器之外的解析碰撞检查仍会把有效梁实体作为障碍物，因此悬空和世界轴向管段进入梁体也会显示红色冲突并阻止提交；无效导入梁不会成为宿主或障碍物。

所有当前设备类型也可选择有效 Beam 的底面、侧面和端面；显示几何和端口按该面法线与基准定向，顶面不会成为点位候选。2D+3D 分屏中在 2D 选择 Overlay 点位，会同步成为 3D 面板的活动点位，可直接输入定位尺寸；这不赋予 2D 编辑能力。允许 Ceiling 安装的点位在实际 Ceiling、梁或楼板上被选中后，提供与灯具相同的平面 X/Y 尺寸和相对完成地的标高输入；首次修改会保留其世界坐标并改为独立 Installation reference plane 关系，墙面设备的尺寸逻辑不变。编辑梁不会拖动设备或管线：仍接触该面的关系保留，失效关系会在同一工作区事务中清除为未宿主。仍承载设备的梁会拒绝删除并显示设备身份；未承载时仅清理该梁穿孔，不改写剩余管线坐标。这些可视化记录不构成荷载、配筋、开孔安全区、规范或结构审批结论。

## 数据诚实性与降级

- 仅传递源 JSON 已有的节点和变换；根节点缺失时仅从 `parentId` 为空的节点推导，并显示诊断。
- `slab.elevation` 在 Pascal 中表示从本层 Y=0 向上的楼板厚度；3D 按该厚度挤出楼板，并把位于其 polygon 内、普通落地家具的源 Y 坐标放在楼板顶面之上。墙面/天花附着对象不套用该抬升。
- `roof` / `roof-segment` 缺失时显示“当前文件无屋顶数据”，不得补造屋顶。
- 未承诺的第三方节点保留在输入中并显示信息诊断。
- 不加载 GLB；家具统一以由源 `asset.dimensions × item.scale` 得出的尺寸占位展示，避免在一个场景中并发请求大量模型。

## 展示控制

支持外观、室内、地板、天花及六个镜头角度预设；透视/正交投影；叠放、爆炸、单层楼层模式；完整、剖开、半透明、隐藏墙体模式；墙、楼板、天花、梁、屋顶、门窗、家具、Zone 图层开关。梁层默认开启；创建说明见 [Demo Beam authoring](beam-authoring.md)。默认使用不锁定光标的自由相机：鼠标旋转、右键平移、滚轮缩放。所有展示控制只保存在当前 React 会话。

创建或编辑 Beam 会更新建筑项目数据，但不会重置用户已调整的相机位置或角度；只有用户选择镜头预设或重建画布时才应用预设视角。
