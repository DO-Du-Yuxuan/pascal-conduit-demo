# ADR 0011：对齐 Builder 展示层，保留 Demo 数据与施工工具权威

状态：接受。日期：2026-10-12。

## 背景

Demo 要对齐本地 dsphere Builder 的编辑界面、建筑渲染与导航，便于之后将施工能力接入 Builder。需求同时明确保留施工功能及 Project 4.0 数据规则。Builder、最新 Pascal Editor 与 Demo 的依赖和场景状态已不同，直接使用完整 Editor 会带入另一套节点加载、状态提交和工具快捷键。

## 决定

1. Demo 的统一项目、端口与宿主引用、施工路由、碰撞、测量证据和撤销事务继续由既有领域代码负责。界面和相机只派发到既有动作。
2. 借用 Builder 的界面资源、视觉参数与纯建筑几何；通过明确的适配模块读取源节点，生成临时 Three.js 几何和材质，不将派生值写入原 JSON。复杂建筑形体优先复用规范生成器，避免第二套近似造型逐渐偏离 Builder。
3. 导入建筑位姿与 Builder 累计楼层高度通过共同的显示矩阵接入；建筑、施工对象与尺寸线一起显示变换，鼠标点/射线在拾取后反变换回 Demo 编辑坐标。原保存坐标、测量依据和业务约束不重写。后续接入 Builder 时须显式接管这条坐标映射，不能重复变换。
4. 保留 Demo 的 WebGL 与按需刷新，使用本地深度/法线屏幕轮廓替代三角网格描边；不为视觉对齐引入完整 WebGPU 后处理、Next.js 页面或 Builder 服务端/账户依赖。
5. 空格作为临时相机平移，原来的显式选择快捷键改为 Builder 的 `V`。相机事件在派发施工拾取之前分流，不清草稿或确认落点。
6. GLB 家具和真实资产的加载留在后续范围。本轮的建筑、施工系统与图纸仍在一份 Project JSON 中保存。

## 后果

展示适配可以逐步移入 Builder 的界面、节点与材质注册接口，Demo 的施工业务不需要同步换状态系统。复制或适配的生成器需要注明来源，并在目标 Builder 更新后以源尺寸、变换、洞口和代表性样例核对；不能把共享技术谱系当作当前几何完全相同的证据。

Renderer 降级和资产访问失败属于会话显示诊断；未知未来节点和字段继续保留，不虚构其几何，不改写保存数据。整合的真实数据权威切换仍需独立 ADR 和往返验证。
