# ADR 0012：只读有效建筑参数与 Demo 本地梁节点

状态：接受。日期：2026-10-13。

## 背景

用户需要继续开发 Demo 的施工 feature，暂时无法等待正式 dsphere 整合；本轮明确只允许修改 Demo。真实 Project 4.0 文件同时包含完整门窗参数、部分缺省墙/天花字段以及新版显式 Level 高度。把默认值写回节点或直接替换为宿主场景 store，会破坏原始字段及梁的标高依据。

## 决定

1. 建筑保存源与有效参数分离。读取时返回原值、有效值和来源；显式值优先。源 Level 有明确 height 时采用层顶/覆盖板的缺省高度解释，否则采用当前 Builder 的旧缺省。几何和实体定位共用解析值，不将其作为建筑节点修改提交。
2. 现存施工坐标、端口和连接不因显示修正而移动；派生测量结果可以根据正确实体重新计算，但保存的依据和来源不能丢失。Beam 的旧 2700 mm 派生依据单独保留，不用补过默认值的 Ceiling 副本参与 Beam 验证。
3. 门窗可见部件、墙切口和门窗实体见证使用共享纯几何；保持只读，不引入操作工具。尚未支持的变体明确降级，不声称与全部 Builder 参数完全等价。
4. 把现有梁的参数定义、纯几何、拾取描述和 2D/3D 显示组织成 Demo 本地节点模块。domain 的验证、作者规则、碰撞和持久化权威不变；工作区继续拥有交互与事务。
5. 不修改 dsphere，不运行跨工作区动态导入，不引入另一套 scene/undo authority。未来宿主通过适配器读取本地节点接口，正式融合另行设计和验收。

## 后果

正确读取缺省参数后，画面或派生尺寸可能与旧 Demo 不同；这不是自动改写已保存施工数据。源格式与当前 Builder 的历史合同不能混为一谈，需要保持明确的解析来源与 fixture。

本地纯几何仍需维护来源与兼容性测试，不能消除复制代码的漂移风险。模块化降低未来接入成本，但不等于完成 dsphere 插件集成。未知字段/稳定 ID/源节点原样保存、Beam 唯一建筑作者以及 Project 4.0 单文件合同继续适用。
