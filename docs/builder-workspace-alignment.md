# Builder 界面、建筑渲染与导航

本轮以本地 `dsphere-main` 的 Builder 为对照，`editor-main` 只提供实现参考。两者已有分叉，不能将最新 Editor 当作 Builder 的同一版本。

## 工作区

- 使用 Builder 的暖纸色界面、Barlow 字体、控件与侧栏层级、圆角画布和底部操作栏；部分公共操作图标直接使用 Builder 的随仓库资源。
- 左栏提供「场景 / 系统 / 图纸」。场景树只浏览、选择和按既有会话规则隐藏建筑对象；名称、ID、几何及未知字段不会被场景树修改。眼睛可逐个隐藏和恢复，会同步反映 3D 建筑图层开关；关闭的图层可通过节点眼睛重新开启，同时清除该节点的会话隐藏，其他单独隐藏的对象保持隐藏。源数据 visible:false 仍只读，不由眼睛覆盖。搜索、展开/收起与恢复隐藏对象不保存进 Project JSON。
- 十个系统入口、设备卡片、参数面板和右侧选中对象属性保留原来的业务操作。梁从建造入口进入，不依赖先选择施工系统。尚未接入的 Builder 建筑工具仍明确禁用。
- 2D、3D 和可拖动分屏继续共用一个活动楼层。切换模式隐藏已挂载视图，不清空施工草稿、撤销历史或文档；隐藏视图不接收键盘输入。
- 左上视图切换按 Builder 的 3D → 2D → 分屏顺序，使用 32 px 高控件、14 px 建筑/蓝图原图标与 12 px Columns2 分屏图标。
- 3D 右上角「视角 / 图层」在同一排布局，菜单互斥展开；点击菜单外部、焦点移到外部或按 Esc 时自动收起，菜单内调整选项保持展开。视角菜单提供会话内地面/网格与阴影显示开关、透视/正交与等轴、顶、前、后、左、右预设。阴影默认关闭，可勾选“显示阴影”开启；关闭阴影会同时停止光源投影与渲染器阴影采样，保留 Studio 照明、材质和轮廓线；开关不写入 Project JSON。相机预设是显式动作；创建对象或更新场景范围不会自动重置相机。
- 未导入项目时展示本地文件导入入口；工作区仍不会自动载入样例。窄屏侧栏可收起，底部工具栏横向滚动，版本信息仍可见。

## 导航与施工输入

| 视图 | 手势 | 行为 |
| --- | --- | --- |
| 3D | 左键 | 原有选择、设备端口与施工落点 |
| 3D | 右键拖动 | 旋转 |
| 3D | 中键或空格 + 左键拖动 | 按屏幕方向平移 |
| 3D | 滚轮 / 捏合 | 透视推进或正交缩放 |
| 2D | 左键 | 原有选择、测量与标注交互 |
| 2D | 右键、中键或空格 + 左键拖动 | 平移图纸 |
| 2D | 纵向滚轮 / 捏合 | 指针位置缩放 |
| 2D | 纯横向触控板滚动 | 平移图纸 |

空格不再切换选择工具或清除路线；`V` 和底部选择按钮负责显式切换选择。相机指针手势不会派发到设备、宿主面、端口或梁参考面的落点处理。输入框和可编辑文本中的空格继续输入文字；失焦与松开空格结束临时导航。

顶视等相机预设保持即时切换；预设与环绕命令会主动请求按需渲染的第一帧，避免等待下一次鼠标交互才应用相机更新。

沿用 Demo 的近距离推进、穿过建筑与施工对象、世界地面最低相机高度和零边界摩擦，不采用 Builder 旧轨道相机的 10–100 m 距离限制。`L`、`D`、`Shift`、世界轴方向键、`Tab` 穿透、`Enter`、逐步 `Esc`、多选与删除保留原来的施工语义。测量过程中右键拖动可以导航；右键单击仍取消未完成的手工测量。

## 建筑显示

- 默认采用 Builder Studio 的背景、墙/楼板/天花/屋面角色色、环境光、半球光、主辅方向光、阴影与 ACES 曝光。
- 深度和法线屏幕轮廓使用 1 px 采样半径、50% 线强度。CSG 的共面三角切分不是建筑边线。线、标尺和临时辅助面不参与轮廓缓冲；WebGL 渲染继续按需刷新，避免引入原发布 Viewer 的完整 WebGPU 链路。
- 同层墙体使用共享的 Pascal 拼接轮廓挤出，门窗、槽与穿孔通过实体切除显示。内外表面材质与边缘分槽；显式材质优先于默认角色色。几何失败走会话内降级，不修改源建筑或施工记录。
- 柱与栏杆读取源截面、轮廓与装饰参数，2D 同步显示对应足迹。它们只读显示，不新增施工宿主或测量资格。
- 楼梯从源 Stair/Segment 构造真实踏步、平台、支撑与栏杆；屋面使用源 RoofSegment 的坡面/折面参数及父子旋转，不再以一整块楼梯盒或水平屋顶盒替代。
- 有效的小尺寸按源值绘制，不为可读性把建筑几何强行放大。建筑长度仍是米，施工 `Mm` 参数仍是毫米。既有楼层/宿主编辑坐标与施工尺寸算法保持原来的规则。3D 的共同显示矩阵读取 Building 位移/旋转和 Builder 累计层高；建筑、施工对象与尺寸线使用同一矩阵，事件点与射线在拾取后反变换回原编辑坐标，相机方向也反变换后供定位标签使用。此映射不转写保存坐标，不改变显式/派生测量依据。
- 2D 建筑使用 Builder 的浅色画布、深色墙体与楼板配色。施工图的管线系统色、物理管径比例、符号、图例、标注和测量证据保持独立。

家具 GLB 与真实资产加载属于后续范围；本轮继续使用保存的资产尺寸与比例展示占位。第三方或未来节点必须无损保存，但没有明确几何定义时不会虚构形体。材质或纹理资源不能解析/访问时使用可识别的角色材质降级，不将降级值写回项目。

## 数据与后续整合

Project 4.0、稳定项目/节点/端口 ID、十系统容器、Drawing 的测量依据和来源、导入建筑只读边界均不变。Builder 的场景 store、工具注册和 undo/redo 没有取代 Demo 的业务 authority。决策见 [ADR 0011](adr/0011-builder-presentation-with-demo-data-authority.md)。

对接入口：`src/ui/` 管理界面部件；`src/three/BuilderNavigation.tsx` 与 `camera-navigation.ts` 管理相机输入；`BuilderInk.tsx`、`BuilderLighting.tsx` 和 `builder-presentation.ts` 管理画面；`builder-wall-geometry.ts`、`builder-geometry.ts` 和 `builder-materials.ts` 管理建筑适配。施工领域逻辑仍位于 `src/domain/`。

复核时应使用同一份统一 JSON，检查视图切换、侧栏和分屏、真实源尺寸、墙洞与施工槽孔、临时导航不落点，以及导出重开后的施工连接和 Drawing 证据；共享渲染或几何变更运行完整 `npm test` 与 `npm run build`。
