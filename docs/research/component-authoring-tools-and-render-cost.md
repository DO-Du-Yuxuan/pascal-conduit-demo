# 精细管件、底盒的制作工具与渲染成本

日期：2026-10-09。研究范围：conduit demo 与新版 editor-main 源码、Blender/FreeCAD/Three.js 官方资料。只读研究与独立几何计数探针，不修改应用代码；没有运行场景性能基准。

## 模型可以直接由代码生成

程序员可调用圆柱、圆环、扫掠、布尔、倒角等高层工具，无需逐个填写所有顶点。已查的 Pascal DWV 管件渲染路径没有下载 CAD/GLB 管件的步骤。其美观来自承口、肩部、口沿、止口、材质和曲线过渡，不等于模型来自外部资产库；源码快照不能确认作者使用过哪些参考图、建模工具或AI辅助。

[Pascal承口/肩部/口沿](../../../editor-main/packages/nodes/src/pipe-fitting/geometry.ts#L36)使用 CylinderGeometry 与 RingGeometry；[弯曲主体](../../../editor-main/packages/nodes/src/pipe-fitting/geometry.ts#L122)使用Bezier曲线和TubeGeometry。28段圆周和32段扫掠是显示细分参数。尺寸仍有经验公式，不能直接当电工管产品尺寸。

Demo 当前[管件与底盒](../../src/components/ConduitScene.tsx#L26)：底盒用BoxGeometry；直接是封闭圆柱；标准弯头用少量点生成曲线和TubeGeometry；三通按端口生成三段圆柱。缺少开口、盒壁、敲落孔、螺丝柱、承口肩部和实际管件轮廓。其尺寸和端口已经是业务数据，但未绑定真实产品。

## 制作软件与保留规则的格式

- Blender：适合细化外观、倒角、材质；Geometry Nodes通过节点连接表达程序化操作。[官方节点说明](https://docs.blender.org/manual/en/4.4/modeling/geometry_nodes/introduction.html)。保留.blend作为源，导出GLB用于网页显示。导出评估后的网格不等于把Geometry Nodes完整规则带到浏览器；[官方导出说明](https://docs.blender.org/manual/en/5.1/addons/import_export/scene_gltf2.html)明确Apply Modifiers输出求值后的mesh。
- FreeCAD：适合按尺寸做壳体、壁厚、孔、螺丝柱等，保存参数和特征历史；[官方功能说明](https://www.freecad.org/features.php?lang=eng_EN)。原生FCStd保留模型源；STEP可作精确形状交换，但不应视为原生完整参数生成历史。后续转换成网页网格资产并补产品/端口数据。
- 软件选择是工作流建议，不强制放弃已有SketchUp技能。固定规格模型也可以继续用SketchUp制作。

用户可以做外形并维护规格，AI/开发者负责软件接入和必要规则。无需要求每个精细固定零件都用浏览器代码重建。

## 能否模型转代码

通用mesh→任意正确的参数化规则，没有在当前项目发现现成转换器；一个86mm底盒的形状不能唯一决定变宽时孔位、壁厚和安装耳的变化规则。

可以开发受限的导出流程：建模软件保留部件名称、轴、草图、拉伸/旋转/扫掠/阵列/布尔/倒角及参数关系；导出支持的操作和参数为中间JSON；浏览器生成器执行这些规则。两端支持哪些操作、如何对应必须明确，不是任意CAD历史都能自动转换。

另一条路径是保留参数化CAD或Blender源文件，在受控后台/离线工具中重建并导出模型，网页读取结果。无需把整个CAD建模器翻译成Three.js，但需要新建生成与发布管线。

对当前固定采购规格，优先制作产品模型，导出GLB，并配产品ID/版本/尺寸/材质/端口局部坐标/方向/孔径/承插/计量规则；选择另一规格可加载另一资产。连续管身保留中心线程序化绘制。GLB与工程数据并行，并不妨碍连接、BOM或计算。

## 细化程度建议

管件先做影响辨识和连接的细节：正确外形和弯曲过渡、承口、肩部、口沿、止口；底盒先做外壳和盒壁、开口、该型号的敲落孔/安装孔、螺丝柱和固定耳。每项以实际产品为准，不假定所有底盒结构相同。

商标、表面纹理、小划痕等优先材质/法线贴图；螺纹、很小倒角或隐蔽内部细节按视距和实际需要控制。不把单个GPU mesh当作一件采购对象；视觉子部件不能自行变为BOM行。

## 渲染成本

影响因素分别是三角形数量、对象/绘制批次数、材质与纹理、透明和阴影、几何重建，以及拾取/碰撞开销。程序化和GLB都最终渲染网格，同样复杂度下不能只按文件来源判断速度。

用Demo安装的Three.js执行独立构造计数，结果仅针对这些基本几何，不是帧率测试：

| 基本几何 | 三角形数 |
| --- | ---: |
| Demo底盒BoxGeometry | 12 |
| Demo直管/直接的12段圆柱 | 48 |
| Demo标准弯头16×10 TubeGeometry | 320 |
| Pascal一个28段开口承口圆柱 | 56 |
| Pascal一个28段肩部圆柱 | 56 |
| Pascal一个28段RingGeometry口沿 | 56 |

这说明精细零件通常是增加几个有用形状，不一定要用巨大雕刻模型；但大量子mesh未经合批时，绘制开销会积累。

当前ConduitScene逐实例创建mesh/material，没有查到该层管件/设备使用InstancedMesh或统一几何缓存。已有部分useMemo、ChaseMesh的memo以及按需Canvas渲染，但不等于精细重复对象已优化。

建议新增模型时按产品规格/几何版本缓存，重复件共享几何和材质并尽可能实例化；合并固定同材质部件；近看使用完整结构、远看用简化模型；拾取/碰撞用简单代理和真实端口；布尔挖孔在建模/规格变化时计算并缓存，不在鼠标移动时反复执行。[Three.js实例化说明](https://threejs.org/docs/pages/InstancedMesh.html)说明相同几何和材质可减少绘制调用。

没有实测不能承诺支持多少个精细件或固定帧率。应在用户实际设备和代表性项目上看draw calls、triangles、内存、帧时间及拾取响应，再定细化和LOD规则。
