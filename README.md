# Pascal 施工管线路由 Demo

这是独立的管线编辑 Demo。它以 `pascal-layout-auditor` 的 Parser、二维画布和只读 3D Viewer 为底座，但不展示、不运行或写入任何 G1/G2/G3/G4/S1 评价结论。

默认建筑底图是用户提供的 `sample-data/default-layout.json`，SHA-256：`48526ac17d3b5f6a6ed8f2a63863d8086e53a54762815dbe35ddfc80647d5d1c`。它默认加载且 Overlay 为空；不再使用 Bellevue 作为 Demo。

## Demo 文档合同

`README.md` 是同事与 AI 共同读取的当前能力入口：它记录已经实现的用户行为、数据归属、持久化方式和明确边界，并链接到对应的详细合同。专题文档描述当前行为和实现边界，ADR 记录难以反转的取舍及原因；代码和测试负责验证这些陈述。任何用户可见功能、数据归属、保存格式或边界发生变化时，必须在同一次变更中同步更新 README 和适用的专题文档，不能只改代码。

运行时出现未捕获的界面渲染错误时，Demo 会显示错误名称、信息、调用栈和“刷新并重试”按钮，避免留下无法诊断的空白页。

## 保留的 Viewer 能力

- 原始 Pascal JSON 宽容解析、解析诊断、二维多画布、楼层切换、旋转、平移、缩放、测量、图层和对象隐藏/恢复。
- 支持纯 2D、纯 3D 与可拖动的 2D+3D 分屏；分屏左侧使用当前第一个 2D 画布，切换视图不会重新解析底图或清空 Overlay。
- 3D 外观、室内、地板、天花，以及顶/前/后/左/右/等轴视角。
- 3D 相机只保留世界地面的轻微边界缓冲；墙、天花、家具、管线和隐藏节点均不作为相机碰撞体，可直接穿过。
- 透视/正交、叠放/爆炸/单层、完整/剖开/半透明/隐藏墙体、建筑（含默认开启的梁）与四类管线图层。
- 墙、弧墙、门窗洞口、楼板厚度、天花、楼梯、屋顶数据和家具尺寸占位。无 roof 数据时明确提示，绝不虚构屋顶。

## 管线 Demo

- 插座线路：红色 `#ef4444`，20 mm；照明线路：蓝色 `#3b82f6`，20 mm；网络线路：白色（灰描边），20 mm；消防喷淋：绿色 `#22c55e`，50 mm。
- “点位”工具可手动放置强电箱、弱电箱、入户消防水点、插座、开关、灯具、网络面板和默认朝上的喷淋头；全部使用轻量参数化几何。
- 新线路必须从合法端口开始：红色插座和蓝色照明来自强电箱，白色网络来自弱电箱，喷淋来自入户消防水点。已接源插座、开关和灯具可继续出线；所有已接源线路均可从开放管端续画。网络面板只能接到白线开放端，且自身与喷淋头都是终点。
- 3D 是唯一绘制入口。画管默认开启宿主面正交，左键选择/落点，右键旋转，中键平移，滚轮缩放；`Shift` 点击切换宿主面正交，方向键切换世界轴悬空走管并关闭正交；双击或 `Enter` 完成，`Esc` 取消最后一点。
- 直管、圆角大弯、消防弯头、三通、直接接头、86 检修盒、地面过桥弯、墙/楼板浅槽和穿孔保存在独立 Overlay sidecar。2D 只读显示同一份端口化管网，可选择但不可编辑。
- 2D 只显示管线连续几何和 86 地盒符号，不为弯头、三通或直接接头额外绘制节点圆点；3D 三通按三个物理端口显示圆筒承口。
- 在 2D+3D 分屏中，3D 的起点、实时中心线、圆角大弯、分支地盒和冲突红色状态会同步预览到 2D；临时预览不写入 Overlay，也不产生撤销记录。
- 实时绘制和管段点位预览按浏览器动画帧合并鼠标更新，2D 永久管网与临时预览分层渲染；碰撞空间索引按不可变 Overlay 复用。以上仅减少重复计算，不降低拾取、碰撞、槽孔或显示精度。
- 分支模式沿已有管段实时预览分支点；红、蓝系统插入同色 `86 × 86 × 50 mm` 检修盒，消防系统插入三通；白色网络线路不允许分支。
- 插座、开关、网络面板以及红/蓝分支产生的 86 底盒均采用四面、每面双孔的端口模板；管线在盒体边缘孔位终止，开始续画时需点击具体孔位。插座、开关或分支 86 盒点击已占孔时，盒体会侧移，让同侧另一孔继续承接既有直管并释放被点击孔供新路线使用；旧管不会为追孔而变形。插座、开关和灯具可通过单击、双击或悬停后按 Enter 插入兼容管段，原管段会在设备端口处截止；悬空管段同样可挂载兼容点位。灯具始终水平朝下，接管孔位于圆盘的水平面。喷淋头可安装在消防直管上（含转弯后的直管），中部安装会生成三通和短支管，主管不会穿过喷头。
- 四类系统均按 4000 mm 最大中心线定尺自动插入直接接头。红、蓝、白线管只要中心线发生非共线转向，就统一使用默认 150 mm 相切大弯；梁面上的电气角点则使用直角弯配件。普通跨宿主、多次换面或 Tab 穿透仍按大弯处理；净空不足时禁止落点和提交。消防继续使用标准弯头。
- 管线实体默认不得交叉，冲突草稿显示红色并禁止左键落点、双击、Enter 或“完成路径”提交。例外是同一楼板顶面上红、蓝、白新管与既有红、蓝、白非平行交叉：系统会为新管生成双 45° 地面过桥弯；消防、平行重叠、管件附近及空间不足的交叉仍禁止。共享同一物理端口的接触不算冲突。
- Tab 会冻结按键前最后一段的入射方向，沿同一直线穿过入口宿主；出口确认后重新附着实际目标宿主，并恢复 Tab 前的宿主面正交状态。普通自由/正交模式始终依附宿主面，只有世界 X/Y/Z 模式允许悬空走管。
- Viewer 仅保留施工态。槽与穿孔数据随管线路由立即写入 Overlay，但按钮点击前不显示槽、不开槽也不穿孔；左侧“生成/更新槽孔”在存在尚未应用的变化时亮起，点击后才统一对运行时墙体和楼板执行建筑切割。天花和消防不生成浅槽；只有切割失败的宿主才显示替代槽线。原始 Pascal JSON 永远不被修改。

墙/楼板浅槽宽度默认是管径 + 10 mm、深度是管径 + 5 mm；穿孔直径是管径 + 10 mm。大弯半径固定为 150 mm，定尺长度固定为 4000 mm，不在面板中编辑；槽孔尺寸仍是可编辑的 Demo 参数，不是施工规范结论。消防喷淋默认吊顶内明敷，不生成浅槽。

Overlay 当前版本为 `2.3`，新增稳定 `projectId` 归属，同时保留 SHA-256 作为修订指纹；旧 SHA-only Overlay 会自动兼容并在项目首次成为可写项目时迁移。旧 `1.0`–`2.0` Overlay 还会自动迁移系统名称，并保留为“未接源旧线路”；旧线路在接入合法源之前不可继续分支。用户可从匹配的源设备画到旧线路开放管端，接通后整组旧 Circuit 会恢复为已接源状态。本 Demo 不判断照明开关控制关系、配电负荷、回路容量、喷淋覆盖、间距或消防合规。

## 项目与 Overlay 持久化

当前梁编辑以垂直梁长边的物理面净距输入为准；梁体与端点不可直接拖动。下面关于 Beam 的持久化说明沿用同一规则。

梁的选择编辑采用点位同款的场景物理尺寸线：不能拖拽梁体或端点；场景只显示一条垂直于梁长边、从梁侧面沿该横向射线到首个墙实体表面的定位尺寸。沿 X 轴的梁显示 Z 向净距，沿 Z 轴的梁显示 X 向净距，斜梁显示“垂直梁净距”；墙本身可以倾斜，但不会取墙中心线、墙端、相邻梁或沿梁方向的距离。面板对应数值以 5 mm 精度整体平移梁，不改变长度或角度；找不到相交的墙实体表面时该字段不显示。Pascal 源墙缺少或为 null 的厚度时，渲染和梁吸附都使用 100 mm 默认实体厚度。宽度不会再改变任何端点操纵器，因为梁没有端点操纵器。

项目 JSON 顶层 `pascalConduitProjectId` 是 Demo 的稳定身份扩展，首次导出可写项目时生成一次；内容 SHA 仅标识某个修订版。项目 JSON 与独立 Overlay 分别导出，项目导出始终下载新文件而不会覆盖导入源文件。导入相同项目身份的新修订会保留并重验 Overlay，导入不同身份会建立新 Overlay；两份文档的脏状态独立，任一未导出时关闭或替换工作区会提示。所有导入建筑节点仍为只读，唯一例外是文档化的 Demo `beam` 扩展：3D 可从 Ceiling 下表面创建直线矩形梁，并以名称、截面、长度及真实墙/柱/梁表面捕捉和物理面净距字段按 5 mm 精度编辑；梁体与端点不可直接拖动；其底面、侧面和端面可承载明装管线和全部当前点位（顶面不可选且梁面不生成槽）；从墙面继续绘制时，明确命中的梁面会优先成为下一落点，并在正交锁定时以受约束方向与梁面求交；不能相交时，单击确认当前墙/天花上的辅助对齐点，随后可继续逐点转向梁面；设备几何和端口按所选梁面定向。编辑梁保持既有设备与管线的世界坐标，只清除不再接触梁面的宿主关系，不自动重连、拉伸或改线；仍承载设备的梁拒绝删除并显示设备身份，解除宿主后删除只清理其穿孔。有效梁实体对表面、悬空和世界轴向管线执行独立的阻塞碰撞检查；项目 JSON 保留 Level/Ceiling 关系和明确或 2700 mm 推导的标高依据；Overlay 从不承载梁几何。Beam、设备与穿孔记录只是 Demo 作者信息，不判断荷载、配筋、安全开孔区、规范合规或结构审批。

3D 点位定位采用设备边缘尺寸：选中点位时，场景内会显示最小尺寸线和毫米数值；墙上设备可输入下边缘离地高度，以及到同墙邻近点位或墙端的净距；灯具和喷淋在模型缺少天花、梁时可放到每层默认 `2700 mm` 的安装参考平面，并支持 Ctrl/Command 多选统一改标高。输入框回车或失焦后直接作为一次可撤销操作提交，不需要额外确认按钮。移动已连接设备会短暂高亮并移除相邻管段，保留真实开放管端供用户重新逐点连接，不会自动规划或拉伸旧管。

Beam 作者工具每层提供 Overlay-owned 的 Layout reference plane，可在天花图层隐藏时继续作为交互面；它不写入项目 JSON，也不会移动既有梁或点位。梁起点必须在 Ceiling 区域，终点可自由落点或物理 Surface snap，整根轴线至少须与一个 Ceiling 相交；参考面的确认走 pointer-down，因此不会被相机控制取消。梁工具显示可切换的正交锁定（Shift 同步切换）、物理 Surface snap、自由/捕捉/显式 Ceiling 标高跨越/无效的语义反馈，以及不改变画布高度的创建/拒绝结果；创建或编辑梁保持用户当前相机视角。Ctrl（Windows/Linux）或 Command（macOS）只在按住时允许跨越不同 Ceiling 标高，并始终保留起点 Ceiling 标高。详见 [Demo Beam 作者工具](docs/beam-authoring.md)。

同一 Layout reference plane 也服务于灯具、喷淋头和传感器的新水平点位预览与放置；点位保存的仍是独立的 Installation reference plane 关系，而不是一个虚构的 Ceiling/Layout 宿主。隐藏共享平面不会移动现有点位，并会提示作者改用可见的合法实体宿主；墙面专用设备的宿主规则不变。

画管仍由用户逐点确认：空格保持选择工具，Shift 控制宿主面正交，方向键锁定世界 X/Y/Z，Enter 只完成已确认的点。吸附候选仅包括兼容设备端口、开放管端、合法分支位置和宿主边角；约束不共线时只提供辅助对齐，不建立虚假连接。本 MVP 不提供数字管长输入或自动布管。

## 2D 施工图画布

2D 保持原有工具面板和测量入口，底图采用黑灰线稿，家具素材保留细节并灰度淡化；设备使用以真实中心为锚点的符号，管网按系统着色。网络线路仅在 2D 显示为深灰，3D 和保存颜色不变。

2D 浮动面板分为“建筑图层”和“管线图层”，可分别开关墙体、梁、楼板、门窗、楼梯、家具、空间名称、外围尺寸，以及插座、照明、网络、消防管线和点位图块。梁只显示可选择的灰色足迹，不提供 2D 编辑或永久尺寸文字。浮窗不展示开发统计或解析诊断。点位标注显示设备类型或人工设备说明及 `H=离地高度`，不显示生成编号，也不标注管径、管道上行/下行、方向或墙端定位。双击设备说明可编辑现有 Overlay 的 `device.name`；高度、数量和排列关系继续由模型生成。

房间文字、尺寸数字、测量数字、点位图块和点位标注均使用模型空间尺寸，随图纸缩放保持相对比例；旋转时文字保持正向。“点位标注比例”可在 50%–200% 间全局调整点位图块和点位文字，不影响其他图层。同墙相邻中心距离不超过 150 mm 的点位自动组合：同类型同高度合并数量，水平组合显示左/中/右，重合投影的不同高度组合显示上/中/下。说明块按最近建筑外围边放在外围尺寸之外，使用两排主引线、竖向主干和逐行分隔线。

## 运行与校验

```bash
npm install
npm run verify:sample
npm test
npm run build
npm run dev
```

局域网开发请使用 `npm run dev -- --host 0.0.0.0`，再从其他设备访问终端显示的 Network 地址；不应把 `--host` 写成 `-- host`。

浏览器视觉验收由用户执行；自动化流程不启动浏览器、Playwright 或 CUA。
